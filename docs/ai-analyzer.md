# AI Analyzer

The authenticated `/analyzer` page (`/app/analyzer` locally) is a chat-style workspace with a centered empty-state prompt and composer. A compact market preview, tracked-position count, and linked coverage appear as backend progress arrives, with subtle entrances and a small activity indicator. The answer appears as a Polymarket-inspired blue share card showing the recommended outcome, entry quote, and research counts; it explicitly identifies the recommendation as no trade placed. The entire card links to the market (or the Polymarket homepage when no exact link is available). Three always-visible reasons sit in a row beneath the centered result card, with a horizontally scrollable row on narrow screens. The page inherits the site font and uses readable text sizes throughout. During retrieval, a search status with animated dots and real source links shows the work in progress. Source links and trader details remain available below the reasons. The four-second example uses fictional data and example-domain links; real responses have no artificial delay. Motion respects reduced-motion settings.

Requests with `Accept: application/x-ndjson` receive newline-delimited `progress`, `result`, or `error` events. Authentication and entitlement failures are also sent as error events; JSON callers retain the original status codes and payloads. The frontend handles fragmented chunks, cancellation, interrupted streams, and a 145-second timeout. The streaming server has a 125-second deadline; search and final synthesis each have a 45-second timeout. Disconnecting aborts upstream research and synthesis.

## Live service setup

Deploy both `index.ts` and `research.ts` from `supabase/functions/analyze-market`. The existing server-side `OPENAI_API_KEY` is used for research and synthesis. `OPENAI_ANALYZER_MODEL` optionally overrides `gpt-4.1-mini`; `OPENAI_RESEARCH_MODEL` can independently override the research model and must support Responses web search. No additional search-provider key or database migration is required. The function authenticates the caller and requires an active/trialing subscription; position reads use the caller's RLS permissions.

The service accepts a market link and/or PNG/JPEG/WebP data URL (4 MB maximum) and retrieves market metadata and up to 60 recent tracked positions. It then makes a web-search Responses request, followed by structured pick synthesis. Research asks for exact event/date matching, primary sources, current developments, and counterevidence. Screenshot-only research receives the image to identify the event. Images and research are not persisted by this feature; response storage is disabled. Web search adds tool and model usage costs.

Source URLs come only from search-tool results and provider citation annotations. Stable source IDs connect claims to links; uncited search results are labeled as discovered rather than cited. Unsupported source IDs are removed, and a web finding with no valid citation is replaced with an explicit unverified finding. This validates citation provenance, not whether a source logically proves a conclusion. Research failure or no cited sources is explicitly disclosed and falls back to market context; it never invents sources. Every completed analysis selects an outcome to buy.

Research can retrieve relevant news, official reports, and event context available on the web. Coverage and freshness are not guaranteed, and there is no dedicated sportsbook/injury feed or independent probability model. Multi-market events require a specific link. Screenshot-only input cannot verify the live market price. Quoted prices are snapshots, not executable prices. Trader entries are sampled transactions, not aggregate cost basis.

Validation: `deno test --no-lock supabase/functions/analyze-market/research_test.ts` covers citation provenance, URL rejection, stable IDs, fragmented SSE decoding, search counts, and uncited-response handling. Live provider behavior still depends on configured model/key access.

Before public launch, add a durable per-user usage quota suited to the pricing plan; current protection is subscription authorization and a bounded request size/output. Live API behavior needs an integration check in an environment with configured secrets. No deployment is performed by adding these files.
